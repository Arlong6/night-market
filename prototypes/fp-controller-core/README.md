# fp-controller-core

**假說**：第一人稱控制器 GDD 的 AC 節宣稱「31 條今天就能跑，成本約一個 `.cs` 檔 ＋ 一次 `run.sh`」
——**那句話是真的嗎，而且跑起來會紅在哪裡？**

這個原型的目的不是實作遊戲，是**執行 creative-director 在 2026-09-26 評審裡留下的可證偽檢定**：

> 若 31 條 T0 紅燈集中在 **AC6／AC13③／AC1③**（被點名「文件算錯」的那三條）
> 而 Core Rule 衍生條目（AC8a／AC8b／AC9／AC10／AC11／AC21）**全綠**，本裁決為真。
> **若反過來，則 C8／C9 的碰撞模型才是真正該被重審的東西，根因排序要重來。**

## 怎麼跑

```sh
./run.sh
```

本機無 dotnet SDK，使用 Unity 6.3 內附的 Mono（`mcs` 上限 C# 7.2，是專案目標 C# 9.0 的子集）。
無需 Unity 專案、無需 `Assets/`、不碰 PhysX／NGO。

## 發現

### 1. 🟢 檢定結果：creative-director 的根因排序**成立**

被點名「文件算錯」的三條，**修訂後全部通過**（AC6 的 13 幀、AC13③ 的兩倍、AC1③ 的動作表）。
Core Rule 衍生條目 **AC8b／AC9／AC10／AC11／AC21 全綠**。
⇒ **C8／C9 的碰撞模型是健全的**，不需要重審；壞的確實是文件的自我稽核層。

### 2. 🔴 唯一的紅燈是一條**十位專家都沒抓到**的文件缺陷：AC8a③

```
AC8a 測試向量：ghost 距原點 0.50，接觸中心距 2·r_c = 0.6
  重疊深度 p           = 0.10 m
  AC8a③ 斷言的位移      = 0.5 × p = 0.05 m
  每幀預算 v/60         = 0.0245 m
  0.05 > 0.0245        ⇒ 直接違反 AC3／C12（預算涵蓋解除穿透位移）
```

**AC8a③ 與 AC3 互相矛盾，而且是不可能同時成立的那種。**

三件值得記下來的事：

1. **這不是 2026-09-26 修訂改出來的。** 舊預算（v=1.39）是 0.023167 m，`0.05` 同樣超標。
   **這條 AC 從寫下的那天起就不可能通過。**
2. 🔴 **`0.05` 只在「C12 被誤讀」的世界裡才合法**——若預算真是誤讀的固定 0.147 m/幀，
   則 `0.05 < 0.147` 成立。**換句話說，AC8a③ 是照著 AC6 專門要抓的那個誤讀寫出來的。**
3. ✅ **鑑別力倖存**：讀 ghost 得 0.0245 m，讀 owner 真值得 0 m——**0 與非 0，沒有灰帶**。
   AC8a 的功能（區分兩種實作）完好，壞的只有那個具體數字。
   這與 AC6 先前的情況**形狀完全相同**。

✅ **已套用（arlong 2026-09-26 批准）**：AC8a③ 改為
`大小 == min(0.5 × (0.6 − 0.50), 每幀預算) == 0.0245 m`，測試對齊後通過。
測試另加一條前提斷言「本向量的原始解除穿透必須超過預算」——否則 `min` 沒在做事，
這條 AC 就退化成不測預算交互的版本。

### 3. ⚠ 一條實作端的真缺口（已修）：C14「回前景第一幀不移動」

AC25③ 第一次跑是紅的。原因不是文件錯，是**我漏實作了 C14 明文寫的規則**：
只把速度狀態歸零並不夠——加減速斜坡會在恢復採納的**第一幀**就給出 0.306 m/s，
位移 5.1 mm。需要一個明確的「恢復幀仍不採納輸入」旗標。
**這正是 C14 那句話存在的理由，而它很容易在實作時被讀成「歸零速度就好」。**

### 4. ⚠ 實作端被迫發明的東西（文件沒有給，我猜的）

這三項是**規格空白**，不是實作細節。它們的值目前由程式碼決定，而那是錯的擁有者：

| 項目 | 我填的值 | 文件狀況 |
|---|---|---|
| `input_cancel_threshold`（C10 的「輸入被持續抵銷」判定） | **0.5** | GDD 只**否決**了「淨位移為零」的實作，**沒給正確定義**。AC14 把待定義的謂詞原封不動搬進驗收條件 |
| 「仍重疊但本幀未被抵銷」時計時器怎麼辦 | **維持不變**（不遞增也不歸零） | 文件只規定了「完全分離 → 歸零」。間歇按鍵（手指沒按穩）的語意未定義 |
| `time_to_contact` 的封閉式（F7） | `(中心距 − 2·r_c) / closing_speed` | **F7 從未給出公式**——本檔唯一一條沒有公式的「公式」 |

⇒ ✅ **三項已於同日補進 GDD**（C10 補可判定謂詞與計時器三條語意、F7 補 `time_to_contact` 封閉式與短路求值順序、
Tuning Knobs 新增 `input_cancel_threshold` = 0.5 🔬 並進 registry）。原型碼裡的值現在是**引用**文件，不是替文件決定。

### 5. 📋 AC23 的記錄值與模型值不可直接比較

實測四人分離 **0.2833 s**，模型值寫 `0.2167 × 3 ≈ 0.65 s`。
**兩者不可比**：本測試的四人起始位置是互距 0.05 m，不是每一對都處於 `2·r_c` 的最深重疊。
AC23③ 寫的是「記錄」不是「斷言」，所以這不算紅燈——
但**若日後有人想把它改成等式斷言，必須先定義起始佈局**。
