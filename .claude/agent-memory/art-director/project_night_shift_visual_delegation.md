Night Shift (大夜班)'s gameplay system GDDs (e.g. `design/gdd/machine-interaction.md`, system #5) contain a "Visual/Audio Requirements" section that gets filled by art-director acting as a subagent contributor, with a strict division of labor stated inside the GDD itself: the Visual/Audio Requirements section states only visual **requirements and constraints** (what must be perceivable, world-space vs HUD, and why) — asset specs (resolution/poly/format/naming) belong to `/asset-spec`, and HUD-specific graphics belong to system #11 (HUD). Other gameplay GDDs in this project (#4 攜帶與交付, #7 客人系統, #14 音效, #11 itself) are likely to request the same kind of contribution later — see [[subagent-report-only-mode]] for how to operate when that invocation arrives as a report-only subagent call.

The art bible is `design/art/art-bible-night-shift.md` (Sections 1-5 + 8 complete as of 2026-09-29; 6/7/9 pending prototype validation). It is unusually mature for pre-production and encodes several hard, reusable rules that will recur across every future Visual/Audio Requirements contribution: a hard 2-hue world-space color-privilege quota (互動黃 `#FFD23F` / 警示紅 `#E0392B` only, §4.3 — soup-amber is exempt as an "always-on" ambient color, not a privilege color); a 3-layer material system with different rules per layer (背景層 S≤0.35 decorative density / 互動層 unlimited-but-quota'd / 演出層 unlimited, §5.1); a headtop-icon shape budget (pool A ≤14 total silhouettes across family+named+status icons, §4.3); and a shape-over-texture identity philosophy (支撐原則2) that explicitly does **not** apply to 2D symbols/icons (carve-out formalized 2026-09-21, §5.6) — 2D symbols are texture by nature since "剪影即其全部."

**How to apply:** Upstream gameplay GDDs in this project are increasingly pre-baking visual concepts in their own Edge Cases sections before art-director is even invoked — e.g. `machine-interaction.md`'s own E0.1 already defined the SKU-slot interaction model (slot width 30-40cm, ray distance ≤1.1m, "product mesh = identity, no text menus") before asking art-director for the Visual/Audio Requirements section. Always read the calling GDD's full Detailed Design / Core Rules / Edge Cases before drafting — the visual contract may already be half-specified there; the job is to complete it consistently, not invent from scratch. Also verify which states are actually in MVP scope before designing visuals for them: e.g. `machine-interaction.md` C11 explicitly scopes `OutOfStock` / stock-depletion queries to the `Shelf` family only in MVP (Oden/Microwave/CoffeeMachine "walk up and wait long enough, always available" — no depletion mechanic exists for them yet), so a prompt that casually mentions "空鍋格" (empty oden pot) may be asking about a state that doesn't exist yet — flag this rather than inventing a visual for it.
