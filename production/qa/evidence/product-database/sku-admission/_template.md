# SKU 准入審查 — `[sku_id]`

> 規格來源：`design/gdd/product-database.md` — Player Fantasy「准入門檻」＋ AC12／AC12b
> 檔名必須是 `[sku_id].md`，與 SKU 表的 `sku_id` 逐字相同（AC12b 靠這個找它）。
> **適用門檻全數 PASS 才可把 `status` 標成 `Active`。**

> ⚠ **r3 格式變更（2026-09-20）：裁決改用獨立的 `gateN_verdict:` 行，標題行不得含
> `PASS` 字樣。** 原因：上一版的標題把三個裁決選項**直接寫在標題文字裡**，
> 而 AC12b 的判準是「含 gate 裁決欄位且值為通過」——於是
> **`cp _template.md [sku_id].md` 一個字不填就會通過**。
> AC12b 存在的全部用意是把「人有沒有判斷過」機器化，而那個判準在範本的第一行就被打穿了。
>
> ⚠ **因此本檔全文（含本段說明）刻意不出現任何「gate 編號＋冒號＋通過值」的字面**，
> 否則說明文字本身會變成下一個漏洞。裁決值請填 `PASS`、`FAIL` 或 `N/A`。

## 新鮮度（r3 新增，AC12b 逐一比對；不符即視為本審查已失效）

門檻 1／3 稽核的是**當時那個字串**的音韻性質，門檻 6 稽核的是**當時那張圖**的剪影。
改了標籤或改了 icon 稿之後，這份紀錄就靜默失效了，而檔案還在、AC12b 還是綠的。

| 欄位 | 值 |
|---|---|
| `label_at_review` | （當時的 `display_label` 逐字） |
| `icon_hash_at_review` | （當時受測 icon 來源資產的內容雜湊；非 `nameable` 填 `N/A`） |

**門檻適用範圍**（依 SKU 類型，見 GDD「門檻的適用分級」）：

- `nameable == false`（家族填充型）→ 只需 **門檻 2、4、7**，標籤上限 **6 字**
- `nameable == true`（指名型）→ **門檻 1-7 全部**，標籤上限 **4 字**
- 不適用的門檻請填 `N/A`，**不要填 PASS**——對沒有指涉對象的門檻宣稱通過，
  會讓這份紀錄失去它唯一的用途。

⚠ **測試對象必須是最終匯入資產，不是草圖。** 這一條與 `nameable: false → true`
   的翻轉在同一個 commit 發生，所以資產一定已經在了。
⚠ **母體是頭頂符號總表**，不只其他指名 icon：家族 icon、其他 `nameable` icon、
   隊友四形狀徽章（§4.5）、超時驚嘆號（§4.5）、完成打勾印章（**§4.5**，r3 引證修正
